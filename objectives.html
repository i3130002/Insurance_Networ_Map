UAE Insurance Network Map

Project objectives and scope notes

This project aims to provide a public, static map of UAE healthcare providers. A user selects an insurance plan and sees the providers associated with that plan on an interactive map.

Primary objective

Build a publicly accessible map that helps users find UAE healthcare providers relevant to an insurance plan.

User-facing objectives

  • Show healthcare providers across all eight UAE emirates.
  • Filter providers by insurance plan.
  • Display each provider's type, name, emirate, area, address, and telephone number.
  • Provide a Google Maps lookup link for each provider.
  • Provide an optional Google AI search link for each provider.
  • Use clustered, color-coded map markers so large provider sets remain usable.

Data objectives

  • Combine UAE Ministry of Health data with existing provider data.
  • Deduplicate providers by normalized name and emirate.
  • Keep the best available address and coordinates for duplicate records.
  • Validate coordinates against UAE geographic bounds.
  • Track providers without usable coordinates separately.
  • Generate plan-specific JSON datasets for the website.
  • Keep source data and rebuild steps documented and reproducible.

Insurance-network objectives

The long-term goal is to show providers genuinely covered by each insurance plan. Network evidence should be visible to users and ranked by reliability.

  1. Official insurer network lists, when available.
  2. Known healthcare-chain affiliations.
  3. Emirate coverage as a clearly labeled fallback approximation.

Maintenance objectives

  • Rebuild website data from source data through scripts.
  • Add official insurer network lists under sources/networks/.
  • Finish geocoding the remaining provider backlog.
  • Replace emirate-based approximations with verified network membership.
  • Review possible false duplicate merges.
  • Keep provider and plan data extensible.

Questions for future scope decisions

  • Is this primarily a provider directory or an insurance eligibility tool?
  • Must insurance membership be accurate enough for real treatment decisions?
  • Should users filter by provider type, emirate, distance, or specialty?
  • Should stale or uncertain provider records remain visible?
  • How often should provider and insurer data be refreshed?
  • Are the Google AI search links required or merely convenient?

Prioritized vertical implementation plan

Complete each slice end to end. Do not start the next slice until its success check passes. The first slices make the map useful quickly. Later slices improve accuracy and coverage.

1. Make the current map reproducible

  1. Make the data build scripts use paths relative to the repository.
  2. Run the build from a clean checkout.
  3. Confirm that all generated files required by the website are produced.
  4. Record the exact build command in the maintainer documentation.

Success check: A clean checkout can regenerate the website data and open the map without manual path changes.

2. Deliver one trustworthy provider map

  1. Use the validated provider registry as the single map input.
  2. Show provider markers with type, name, location, address, and telephone.
  3. Keep invalid-coordinate records out of the map and in the backlog.
  4. Check representative providers from each emirate and provider type.

Success check: Users can open the site, see valid UAE markers, and inspect correct provider details.

3. Add useful plan selection

  1. Load plan metadata from data/plans.json.
  2. Group plans by insurer in the selector.
  3. Load the selected plan's provider dataset.
  4. Replace the previous plan layer when the user selects another plan.
  5. Show the number of providers loaded and display a readable error when loading fails.

Success check: A user can select every configured plan and see the expected provider count without stale markers from another plan.

4. Add basic provider discovery

  1. Add filters for emirate and provider type.
  2. Add a provider-name search.
  3. Keep filtering client-side while datasets remain small enough for the browser.
  4. Update the visible count after every filter change.

Success check: A user can find a named clinic, restrict results to an emirate, and restrict results to a provider type.

5. Finish coordinate coverage

  1. Process the geocoding backlog in small, resumable batches.
  2. Accept coordinates only when they fall inside the UAE bounds and match the expected emirate.
  3. Keep failed and uncertain records in a review list.
  4. Regenerate all derived datasets after each completed batch.
  5. Compare counts before and after each run.

Success check: The backlog count decreases, no accepted coordinate falls outside the expected emirate, and the website exposes the newly mapped providers.

6. Make network membership accurate

  1. Collect an authoritative provider list for one insurance plan.
  2. Define the source format and provider matching rules.
  3. Join the official list to the normalized provider registry.
  4. Record unmatched official providers for review.
  5. Show official, chain-based, and geographic matches with distinct labels.
  6. Repeat the process plan by plan.

Success check: At least one plan contains only confirmed network members, its source is recorded, and the UI does not present geographic approximations as confirmed coverage.

7. Add operational data checks

  1. Check required provider fields, valid emirate codes, provider types, and coordinates.
  2. Check that every plan references an existing generated file.
  3. Check that plan counts match their files.
  4. Check that provider indexes used by network assignments exist.
  5. Run the checks after every data rebuild.

Success check: A broken or inconsistent data build fails clearly before deployment.

8. Improve the public user experience

  1. Make the map and controls usable on mobile screens.
  2. Explain the difference between confirmed and approximate network membership.
  3. Show data date and source information.
  4. Improve keyboard access, focus states, contrast, and popup readability.
  5. Add a clear empty-state message when filters return no providers.

Success check: A first-time user can understand what the map shows, use it on a phone, and tell whether network information is confirmed.

9. Establish refresh and release procedures

  1. Document where new provider and insurer data comes from.
  2. Define how often each source should be reviewed.
  3. Keep source dates and data changes visible in the repository.
  4. Run the data checks before publishing.
  5. Publish only after representative plan and provider checks pass.

Success check: Another maintainer can update the data, verify the result, and publish the site without relying on undocumented steps.

Current wording should not claim that a provider is covered by a plan unless an authoritative insurer network source confirms it. The current data more reliably shows providers located within a plan's covered emirates.
